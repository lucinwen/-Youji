# 有记：本地 PDF 正文、找回与受限清理检查点

基于 PR #6 `6ef162a3d1e7d888a75c835848915597ed5f7dcf`，独立分支 `feat/local-pdf-text-20261118`。不合并 main。Memos 26.11.0 底座和 MIT 版权保持不变；没有认证、数据库 schema 或权限绕过改动。

## 本轮可运行行为

- 新增显式本地 PDF 命令行：原件读取一次，在受资源限制子进程中用固定 pypdf 7.1.1 提取已有文字；原件 ZIP 与按页正文均通过现有 Memos API 存为 PRIVATE。正文含页码、原件链接、SHA 与解析器版本，可按当前文件类型、类别及正文关键词检索。
- 全部解析与配额计划完成后才写入。加密、损坏、无文字、页数/字节/分段超限失败关闭。没有 OCR、ASR、模型调用或网页采集；PDF 页码是人工回源线索，不是 PDF.js 页内查看器。
- 提取正文及文件名置于安全长度的 Markdown 代码围栏，防止内容中的图片、HTML、反引号被当作活动内容；用户可编辑正文，原始提取段保留为附件。编辑后重试报告冲突，不覆盖。
- 写入前查同账户原件 SHA，发现其他已知导入根则拒绝重复。它不是数据库唯一约束，旧入口仍未全向识别新 PDF 根，不承诺并发/跨入口全局去重。
- 新增清理预览与执行命令：从同一原 PDF、类别、账户重新计算固定目标 ID，绝不沿正文链接删除。执行须确认具体根 ID，并显式接受上游全部评论子树（含归档、嵌套评论）的删除。正文/附件校验不符拒绝；逐项重检、正文先删、根最后删、404 可重试。不是 CAS 或组事务，须暂停其他设备编辑；不认证物理擦除和孤儿文件清除。
- 工作台显示有记 / Youji，保留历史 `#拾微` 和路由。新增全部个人记录、归档恢复入口；保存提示解释来源、日期、分类、空间或关键词可能隐藏新记录。卡片展示已提交关键词的首处正文上下文，用 React 文本/mark 显示，不造摘要或转写。
- ZIP 校验在第二条目、非目标条目、重复名、异常尺寸或压缩方法进入解压前拒绝；仍是同步解压，尚无可中止 Worker。

## 开源来源与许可

直接新增运行依赖仅可选 `pypdf==7.1.1`，BSD-3-Clause，完整许可在 `moteary/licenses/pypdf-7.1.1-LICENSE.txt`。官方来源：[pypdf](https://github.com/py-pdf/pypdf)、[7.1.1 LICENSE](https://github.com/py-pdf/pypdf/blob/7.1.1/LICENSE)、[变更记录](https://github.com/py-pdf/pypdf/blob/7.1.1/CHANGELOG.md)。没有模型文件或附加模型许可。本机原有 6.21.4 未用于新流水线，因已公开修复于 7.1.1 的解析内存问题而固定更新版；固定版本和资源限额不意味着不存在未知解析漏洞。

合成中文 PDF 来源、SHA 和字体信息在 `tests/moteary/fixtures/README.md`；ReportLab 仅生成测试样本，不是运行依赖。Readability、Docling、PDF.js、Karakeep、faster-whisper 等仍是独立研究候选，未接入本轮，也没有与同类产品同任务实测比较。

## 实际验证

证据目录：`validation/local-pdf-20261118/`。

- Python **62 项通过**，含真实固定解析器对中英 PDF、空页、加密、损坏、页数限制验证；计划、UTF-8 分段、安全围栏、配额、清理确认等回归。超时和凭据环境断言是子进程调用边界的单元替身测试，不是恶意 PDF 攻击压力测试。
- `pdf-http.json`：**16 项真实解析 / SQLite / HTTP 检查通过**。覆盖中英提取、3 条 PRIVATE 记录、中文＋来源＋类别找回页段、原件逐字节一致、第二普通账户与匿名原件拒绝、第二账户正文拒绝、重复核验、改类别重复原件拒绝、进程重启、用户编辑冲突。
- PDF 恢复测试真实保存了部分记录，再在客户端记录边界注入异常；重跑核验已有项并补齐缺项。清理测试覆盖另一账户确认失败、根正文插入无关链接时拒绝、预览不写入、真实归档评论明确确认后删除、删除边界中断恢复、全部计划记录/原件 URL 不可读、检索归零、无关记录保留。
- 故障注入：真实附件创建后在客户端注入 memo 500，准确报告遗留附件 ID；重试完成后仍有一个明确可定位的未关联附件，测试显式清理它。真实 memo 提交后注入响应丢失，重试为 already-imported，不新增附件、不删除已关联附件。这些是**客户端故障注入＋真实服务存储**，不是服务端网络断流/崩溃实验。
- `legacy-http.json`：**64 项既有真实 API 检查通过**，包括此前隔离环境因依赖缺失受阻的 REST-backed Vitest 跨入口校验；这是组件代码调用真实 HTTP，不是浏览器点击。
- 最终前端、构建数字见本文件下方最终构建记录。

## 浏览器：blocked

正常 `chromium_sandbox=True` 实际启动失败：`socket() failed: Operation not permitted` / SIGABRT，发生在创建页面之前。未关闭沙箱或绕过宿主限制。`browser/results.json`、脱敏 `browser/server.log` 和运行日志已保留；无页面故无法截图。此次探测的服务二进制来自上一个检查点，因浏览器尚未进入 UI，不用于本轮 UI 通过声明；最终源码另行构建验证。

脚本已删除 `--no-sandbox`、合成音频延长到 4 秒、补移动页面错误监听、播放进度与下载字节检查、失败截图和脱敏诊断保存。脚本存在不等于检查已执行。桌面/390px 实际输入、播放、下载、触摸、软键盘、多标签并发、双设备同步、原生录音、真实 ASR 全部仍未验收。

## 剩余可靠性边界

- PDF 目前是本地命令行入口；网页普通上传尚不触发解析。没有自动处理队列、后台解析、任务取消 UI、OCR 或语义检索。
- 512 MiB 地址空间、10 秒 CPU、15 秒墙钟时间、2 MiB 输出等属于进程资源限制，不是完整网络/文件系统沙箱。代码不主动联网，不传 API token，不执行 PDF 脚本；未做完整恶意样本集和禁止外联系统调用测试。
- 跨记录非原子；并发创建仍可能额外上传、并发编辑与最后 DELETE 间仍有窗口。存储清理错误需要管理员核查，404 不证明物理字节已擦除。旧长文的整份清理仍未实现。
- 上传附件后 memo 失败的孤儿风险尚未自动解决：现在返回准确附件及目标 ID，不能误报为自动复用或零孤儿。不能贸然删除可能已经提交关联的附件。
- 搜索是单记录关键词匹配，跨页/段短语可能找不到；仅首个匹配上下文；提取顺序与文字映射需人工核对。
