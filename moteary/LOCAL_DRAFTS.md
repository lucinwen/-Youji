# 手动文字：用户控制的本地草稿

范围仅是“粘贴聊天与文字”的粘贴模式。文件模式仍须自行保留原文件；不会保存聊天账户、音频、附件字节或凭据。未启用时不写入草稿内容，也不会自动读取剪贴板、上传或恢复文字。

## 操作

1. 在自己的设备与浏览器中输入合成文字，核对明文风险，勾选同意后点击“启用本地草稿保存”。之后输入变化会写入本浏览器 localStorage。不要在公共设备启用。
2. 等看到“已在本浏览器明文保存草稿”，再刷新或关闭页面。重新登录同一站点的同一账号，打开手动入口；不会自动回填。确认恢复会替换当前输入，再点击“恢复本地草稿”。恢复后仍需重新预览及确认，才保存到服务器。恢复本身不重新开启自动保存。
3. 想继续在此浏览器保留后续修改，要再次明确启用。停止自动保存不会删除已存草稿。
4. 勾选删除确认后点击“删除本地草稿并停止保存”。删除只涉及这个账号在当前站点的新版 v2 草稿，不删除页面输入、旧版 v1 草稿或服务端记录；损坏的 v2 草稿也可明确删除，不能恢复。
5. 本轮写入或明确恢复过的草稿，在 PRIVATE 记录保存/重复核验成功后有条件清除。同一新版协议的写入和删除共用独占 Web Lock，锁内重读发现另一标签页已更改时，拒绝删除并提示重新核对；未采用的既有草稿不会因另存文字而自动删除。

## 实际存储与隐私边界

Memos 原编辑器使用 `edit/hooks/useAutoSave.ts` 与 `edit/services/cacheService.ts`，按用户/编辑身份将内容、附件元数据、可见性写进 localStorage，500ms 合并写及页面隐藏时刷新。它本来就不是加密或跨端同步。本轮不更改原编辑器的行为，也不自动迁移/读取其草稿。

本入口独立命名空间 `youji:manual-draft:v2:<origin>:<owner>`，同时在数据内核对 owner、origin、版本、类型与大小。界面切换账号重建会话，不会把旧输入写入新账号；另一个账号不展示或恢复前一个账号的草稿。来源是用户元数据，不是身份认证证据。

**这是按账号分开的同源浏览器明文存储，不是账号密码保护的安全保险箱。** 同源脚本、浏览器开发者工具、扩展、共用浏览器配置的人可能读取。只能称当前浏览器配置文件和站点范围，不能保证物理设备隔离；浏览器资料复制/系统备份是否迁移它由用户环境决定。没有本地加密、服务器草稿同步、跨设备同步或自动备份承诺。退出会保留明确启用后保存的草稿，离开公共设备前应删除；清浏览器数据也会丢失。

正文最多128 KiB，标题200字符；禁用存储、配额不足、格式损坏或冲突时停止自动保存、保留页面输入并显示错误。粘贴与草稿保留的是输入区当前文本快照；textarea可能将CRLF规范化为LF，不保证原始剪贴板字节。文件原件保真链路不受影响。页面崩溃只可能恢复最后成功写入的版本；React更新尚未执行、浏览器主动清理或磁盘故障可能丢失最后输入。没有实际浏览器进程崩溃/真机验收，不能保证每次按键持久化。

新版使用 Web Locks 把同一站点、账号的 v2 草稿写入和删除串行化，比较与修改在同一独占锁回调中完成。浏览器不提供 Web Locks 时（例如不支持的浏览器或普通 HTTP 局域网站点）拒绝写入和删除，页面输入仍保留；不回退无锁写入。storage 事件仍用于提醒其他标签页。此保证只覆盖采用该协议的新版标签页，不约束同源恶意脚本、扩展或直接操作存储的代码；也不是浏览器崩溃持久性保证。

旧版 v1 使用独立键；新版仅提供读取、确认恢复到输入，不删除或修改旧键，不静默迁移。旧标签页不能覆盖新版 v2 草稿。旧草稿仍以明文留在浏览器，恢复或删除新版不会清除它；需要彻底清除时可在浏览器设置中清除此站点数据，但这也会清除登录状态和其他本地内容。

新版手动粘贴/TXT/Markdown 的 SQLite 保存已采用记录与原件同事务导入，见 [事务导入](ATOMIC_MANUAL_IMPORT.md)。新版 HTML 入口也使用专用 SQLite 事务保存，见 [HTML 事务说明](HTML_ATOMIC_IMPORT.md)。音频、PDF、聊天 JSON 和批量入口仍使用旧保存路径，可能并发双上传并残留未关联附件；本地草稿不能解决它。本会话保留全部已知附件回执，新的 prepared/verified 状态不会抹去已知 ID；它们默认不持久化，刷新前自行保留。需要人工检查残留，不自动删除未知资源，也不宣称并发零重复。
