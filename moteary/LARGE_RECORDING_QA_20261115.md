# 长录音入口核查 · 2026-11-15

## 结论与产品缺口

16 MiB 是有记批量原件入口（网页和 CLI）的限制，不是原生编辑器的上传上限。它确实会挡住一部分长录音。不能只说“支持音频”而不说明容量和入口。

原生笔记编辑器实际调用 `uploadService.uploadFile`，按服务端返回上限且不超过 2 MiB 切片，通过 `UploadAttachment` 分块保存。服务端默认单附件上限是 32 MiB，超过配额拒绝，分块并不绕过配额。受限网络和跨设备恢复仍待验证，音频转写也没有新增。

本次没有盲目放宽 ZIP 批量入口内存限制，也没有要求用户剪碎私密录音。新增明确提示：批量预检失败没有上传任何文件；保留本机原件、转到原生笔记编辑器添加附件，并确认仅自己可见。批量总额超限则提示拆成多批。

## 实际验证

- 真实 CLI：生成 17 MiB PCM WAV（无个人音频），调用实际 dry-run 入口，被安全拒绝；原件 SHA256 前后一致，无凭据、无网络调用。
- 前端定向：33 项通过，1 项既有真实 REST 环境测试因未配置跳过。新增 17 MiB 合成文件测试：批量入口在读取前拒绝且不调用写入；原生上传服务以 9 块传送，重组后与输入字节一致。此项 API 使用桩，不是浏览器/后端端到端。
- TypeScript 与 Biome 全量检查 681 文件通过。
- 新增真实后端 SQLite 测试 `TestYoujiLargeAudioOriginal`：生成有效 WAV 并检查服务端分块保存后的 SHA256；本轮低并发实际执行通过，并同时通过重试与默认32 MiB上限测试（3项通过）；结果见 `validation/large-recording-go-serial-20261115.log`。这是真实服务函数+SQLite+文件落盘集成测试，不是浏览器HTTP端到端。
