# 事件日期与采集时间（Career OS P0）

本功能在 PR #21 基线上增加真实日期存储、编辑和检索。它还不是招聘管理系统，不提供候选人决策或自动下一步；来源引用 P1 尚未交付。

## 最短体验

1. 检出 `feat/career-event-dates-20261119`，按 [运行手册](DEMO_RUNBOOK.md) 的锁定依赖构建步骤构建。该手册原有 #21 checkout 部分是历史基线；本功能请核对本草稿 PR 页面显示的 HEAD。首次试用使用新的 SQLite 目录，不复用私人数据库。
2. 进入有记工作台，以“工作思考”保存两条完全虚构的 `SYN-JOB-2026-017` 材料：需求简报和复盘。当前日期操作在保存后的记录卡上；不需要也不会自动从正文推断日期。
3. 打开卡片“设置或纠正事件日期”，分别填 `2026-11-10`、`2026-11-14`，点击“保存日期”。不确定时留空，或点击“清除事件日期”。
4. 在检索区设置事件起止日或“仅未知事件日期”，点击搜索。它与关键词、来源、分类、空间条件共同在服务器分页前执行。重置后旧记录也可见。
5. 修改事件日期，核对只读采集时间不变；重启同一数据目录，再登录验证日期与原件仍在。原有保存日期筛选仍针对原生创建时间，不等于事件日期。

## 时间与权限约定

- 事件日期按用户输入的 `YYYY-MM-DD` 日历日存储，不转换时区，不默认今天。非法日期拒绝写入。
- 升级后新记录的采集时间由服务器写入；日期接口不能修改它。它反映服务器接收记录的时间，不证明事件发生时间，也不校验机器时钟的真实性。
- 旧记录没有可靠采集时间，显示“历史记录时间（非原始采集凭证）”；来自已有可编辑创建时间，不能称不可变审计记录。不会用升级日期填补历史采集时间。
- 日期元数据接口只允许记录所有者；包括其他账户可读的公开笔记，其日期元数据也不可探测。日期查询必须与当前所有者条件合取。
- 修改日期不改正文、原件、原文件SHA或采集时间。并发改日期采用最后写入生效，没有版本冲突检测。
- 清空事件日期回到未知；删除记录同时删除其同一行中的日期字段，没有独立日期索引残留。

## 构建与回归

沿用仓库 Node24、Go1.27.2 和前端锁文件，无新增依赖或模型。

```bash
pnpm --dir web install --frozen-lockfile
pnpm --dir web release
go build -mod=readonly -o build/youji ./cmd/memos
TZ=UTC pnpm --dir web test --maxWorkers=2
pnpm --dir web lint
MOTEARY_BINARY="$PWD/build/youji" YOUJI_BASELINE_BINARY=/path/to/trusted-pr21-youji python3 tests/moteary/run_career_dates_e2e.py
```

迁移验收脚本先用可信 #21 二进制创建合成旧库，再用新二进制升级，服务只监听127.0.0.1，结束停服并删除合成临时数据库。不要把另一个版本的二进制误当#21基线。输出默认 `/tmp/youji-career-date-validation`，不包含登录凭据。

正式升级前备份数据库与原件；不要在已迁移的新库上直接降级运行#21。需要回退时恢复升级前备份并运行匹配版本。本次实际验证SQLite；MySQL/PostgreSQL已同步schema和代码，但没有实际数据库运行验收。

真实浏览器本轮受云浏览器到执行环境loopback连接及URL策略阻挡；未改监听地址、未关闭沙箱。jsdom测试不是桌面浏览器、移动视口或手机真机验证。没有ASR、语义模型执行或公网服务。
