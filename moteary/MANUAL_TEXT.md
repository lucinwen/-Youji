# 微信聊天与日常文字：手动提供

本入口不接入微信，不读取账户或剪贴板，不解析平台数据库，不导入聊天媒体。使用自己有权提供的文字；演示只用合成资料。它也适合朋友对话、讲座/播客人工稿、工作思考和灵感，不提供自动转写或真实性证明。

## 第一次体验

1. 按 `DEMO_RUNBOOK.md` 启动有记并登录，打开个人素材工作台，点顶部“粘贴聊天与文字”。
2. 粘贴下面的合成文字，或选择 UTF-8 `.txt` / `.md` 文件；每次最多 128 KiB。来源和标题可不填。

   合成甲：明天讨论松涛计划，记得带演示纸卡。
   合成乙：收到，ManualTextNeedle 只用于功能演示。

3. 来源选“微信聊天（手动提供）”，标题填“合成演示”，点“本地预览文字”。此时不写入服务器。正文、HTML、Markdown、链接均按文字处理。
4. 核对正文后勾选确认，再保存。原文和 ZIP 原件固定 PRIVATE，不因工作台当前空间改变权限。
5. 从成功回执打开记录，下载 `.original.zip`，解压核对文本。文件导入保留全部原始字节（含 BOM / 换行）；粘贴保存的是预览时输入框的 UTF-8 快照，不是微信导出文件或剪贴板原始字节。
6. 以 `ManualTextNeedle` 搜索；微信/朋友对话可配合“聊天摘录”类型。若分类、日期或空间挡住结果，使用查看全部个人记录入口。来源不明的文字归入文字类型，讲座人工稿也归文字；播客人工稿归播客。关键词是字面检索，不保证同义改写找回。

## 新版 SQLite 事务保存

当前手动文本入口使用[SQLite专用事务](ATOMIC_MANUAL_IMPORT.md)，将记录和数据库ZIP一起提交，不再调用旧saveAudio分步上传。其他数据库/旧服务器明确拒绝且不自动回退。下列旧上传恢复说明只适用于历史版本；旧版原件不兼容时直接打开已有记录，不迁移、不覆盖。

## 失败与重试

- 预览后改标题、来源、正文或文件，必须重新预览及确认。
- 保存失败时保留当前内容与回执，用同一计划重试。新版事务已提交但响应丢失时，核验已有记录和数据库ZIP，不新增；事务失败会回滚这对新记录/附件。
- 同一账户、原文件名和原字节确定记录 ID；标题和来源不改变 ID。同一原件改这些字段重试会提示内容冲突，不能静默覆盖。打开既有记录核对或人工编辑，而不是反复上传。
- 不同文件名或不同原文视为不同原件，不承诺跨格式/改名去重。修改已保存正文后再导入会拒绝覆盖。
- 停止等待不保证撤销已提交写入。回执可直接打开记录检查状态；多个候选附件会要求人工核对，不会自动删除未知状态附件。
- 默认未保存输入只在页面内存中；刷新、退出或切换账户会丢失。粘贴模式可明确开启[本地明文草稿](LOCAL_DRAFTS.md)，恢复需确认；不是加密或跨端同步。文件、回执仍须自行保留；不能保证崩溃前最后按键已写入。
- 原件含用户提供的所有内容，不是脱敏备份。删除走原生单记录及附件流程；测试只覆盖数据库/API不可读，不证明磁盘物理擦除或外部备份清除。

## 依赖与边界

复用 Memos 的账户、PRIVATE 记录、附件与全文过滤；手动文本使用SQLite事务入口，其他来源的旧 `saveAudio` 协议未在本轮改造。无新增依赖、模型、平台SDK或第三方服务；原有许可证保留。浏览器需 HTTPS 或 localhost 才能计算 WebCrypto 哈希。

本轮真实 HTTP/SQLite 验收、模块测试和 jsdom 交互测试分开记录。手机样式采用可换行布局与较大控件，但没有真实手机/软键盘或浏览器点击验收，不以 jsdom 通过替代。
