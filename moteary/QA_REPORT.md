## QA 发现并推动修复的问题

- 默认 HTTP 重定向可能将认证头带到不同 origin：现在导入器拒绝全部重定向，实际双 loopback HTTP 服务确认目标端未收到请求。
- 记录改成 PUBLIC 后仍被当作私有导入成功：现在明确拒绝，不擅自覆盖用户修改。
- 只检查“有附件”便声称原件存在：现在下载原件归档并校验结构、大小与 SHA-256。
- 附件下载 404 被误当作 memo 不存在并继续上传：404 捕获现仅限最初的 memo 查询，不产生该错误的额外上传。
- Memos 对 JPEG 进行隐私去元数据/重编码，原件字节因此变化；仅按扩展名处理也会漏过未知扩展名图片：导入器现在对所有输入统一保存单文件 ZIP 原件，图片另保留经过上游隐私处理的预览。不禁用上游隐私措施。
- 工作台使用后端不支持的 `display_time desc`，真实请求返回400：改为 `create_time desc` 并以真实账号/标签查询复验。
- 导入器与工作台分类/来源标签不一致：已统一，保留原 kind 作为额外来源信息。

## 可复现命令

先按 `moteary/README.md` 构建完整前端和后端，再从仓库根目录执行：

```sh
python3 -m unittest discover -s tests/moteary -v
python3 tests/moteary/run_api_qa.py
```

完整 API 脚本只使用 Python 标准库，内嵌小型合成 JPEG，默认读取 `build/moteary`。可用 `MOTEARY_BINARY` 指定已构建二进制，`MOTEARY_QA_OUTPUT` 保存无凭据 JSON 结果。它自行分配 loopback 端口、创建临时数据库与合成账号、重启服务并清理进程。不要将它改为指向个人实例。

## 仍未验证或未交付

- 真实模型、OCR、ASR、网页全文归档、语义问答、回答忠实度。
- 真正多设备离线同步、断网期间编辑冲突、原生移动端和 Windows 真机运行。
- 超大文件压力、真实账号恢复、公共部署安全评审，以及完整上游所有可选外部依赖的集成测试。
- CLI 导入器单文件上限16MiB，不等于产品长期目标的200MB。不同文件名但相同字节/用途/批注可能触发原件身份冲突并拒绝覆盖；没有静默丢弃或自动合并。
- ZIP 原件可能保留原图 EXIF 等敏感元数据，默认 PRIVATE 不能替代分享前的内容检查。
- UI 普通图片上传仍遵循 Memos 处理规则，不保证图片原始字节；归档保真能力属于明确调用的导入器，不混称所有 UI 上传已有同等承诺。
